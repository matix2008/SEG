# Проект SEG

Управление несколькими AmneziaWG-серверами с Windows-ноутбука. Архитектура и процессы описаны в `README.md`. Локальный каталог — единственный источник истины, VPS заменяемы.

## Роутинг перед работой с VPS

Сначала определить, какой VPN-клиент активен на ноутбуке: `Get-Service 'AmneziaWGTunnel*'` и `Find-NetRoute -RemoteIPAddress <IP>`.

### Активен full-tunnel клиент AmneziaWG (например `herman-wk1`, `AllowedIPs = 0.0.0.0/0, ::/0`)

Клиент ставит kill-switch: прямой трафик мимо туннеля блокируется на уровне Windows. Ручной маршрут через Wi-Fi не работает: `connect` завершается ошибкой `Permission denied` (WSAEACCES), ping не проходит. Маршрут **не добавлять**. SSH к остальным VPS идёт через туннель (то есть через рабочий сервер), этого достаточно для `sync-servers.ps1`. Это вывод по косвенным признакам (правила брандмауэра без прав администратора прочитать нельзя).

Не отключать и не перезапускать туннель без согласия пользователя: он работает через него. Проверять VPN нового сервера нужно с другого устройства.

### Активен Hiddify в TUN-режиме (`tun0`)

Hiddify перехватывает трафик к VPS: SSH обрывается (`banner exchange timed out`), а ping и tracert показывают ложные значения. Исключений в Hiddify задать нельзя, поэтому маршрут добавляется вручную.

Перед любой работой, которая ходит на VPS (`sync-servers.ps1`, ручной ssh/scp, проверки):

1. Проверить, что трафик идёт мимо `tun0`: `Find-NetRoute -RemoteIPAddress <IP>` должен показать `Беспроводная сеть`, а не `tun0`.
2. Если идёт через `tun0`, попросить пользователя добавить маршрут (нужен администратор) или добавить через UAC: `Start-Process route.exe -ArgumentList 'add <IP> mask 255.255.255.255 <шлюз Wi-Fi> metric 1' -Verb RunAs -Wait`. Шлюз взять из `Get-NetRoute -DestinationPrefix 0.0.0.0/0` (интерфейс `Беспроводная сеть`, сейчас 192.168.1.1).
3. Маршрут не постоянный (без `-p`) и пропадает после перезагрузки.
4. После работы маршрут откатить: `route delete <IP>` (тоже через UAC) и убедиться, что `Find-NetRoute` снова показывает `tun0`.

IP серверов берутся из `servers.txt`. Для проверки туннеля с клиента Hiddify нужно отключить: он перехватывает и UDP.

## Коммиты

Коммиты делает пользователь вручную. Я их не создаю и не пушу. После каждого завершённого блока изменений нужно выдать готовый текст коммита:

- первая строка — краткое описание (до ~70 символов), далее пустая строка и пояснения по пунктам;
- пиши по-русски, в том же стиле, что и остальные сообщения проекта;
- перечисли изменённые файлы и причину изменений;
- без секретов (ключей, PSK) в тексте.

## Вопросы пользователю

Все вопросы я задаю обычным текстом в чате. Интерактивные формы (инструмент `ask_user`) не использую. Если для продолжения нужен ответ, я формулирую вопрос, перечисляю варианты и жду ответа пользователя.

Закрытие пунктов и этапов `roadmap.md` я оцениваю сам и записываю в таблицу «Статус выполнения» (номера выполненных пунктов; для незакрытого пункта — причина). О закрытии пользователя не спрашиваю. Спрашиваю только при развилке или проблеме.

## Запуск скриптов

- Скрипты рассчитаны на Windows PowerShell 5.1. Файлы `.ps1` в UTF-8 с BOM, `.sh` — с LF.
- В моей среде нет интерактивного ввода: `Read-Host` возвращает `null`. Подтверждения можно давать через stdin, но **не одним потоком «y» на все запросы**. Каждый запрос читай и подтверждай осознанно: так один раз было подтверждено security hardening до проверки VPN. При перенаправленном вводе `Read-Host` не выводит приглашение в stdout, поэтому ответы подаются строго по порядку известных вопросов (`y` только для ожидаемых шагов, для hardening и неожиданных вопросов `n`), а затем сверяются по записям `Confirmation:` в журнале.
- Не запускать управляющие скрипты параллельно.
- Все пять `scripts\*.ps1` требуют `-Mode VPN` (или `-Mode SEG`); без него завершаются ошибкой. Для работы с текущими VPN-серверами всегда указывай `-Mode VPN`, например `sync-servers.ps1 -Mode VPN SERVER -Check`.
- Перед `secure.sh` пользователь проверяет VPN с клиента.

## Секреты

В `config/server.env` лежит приватный ключ сервера (копии прежних версий — `config/server.env.*.bak`), в `clients/` — ключи и PSK клиентов. Их содержимое нельзя выводить в ответы и логи. Ключи и конфиги в git не попадают (`.gitignore`). Архивы в `OLD/` могут содержать старые ключи.
